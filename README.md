## Дүгнэлт (debrief)

Хамгийн олон согогийг Supermodel (GUI) аялал олсон: онын таслал (BUG-02), тоолуурын зөрүү (BUG-03), `/old` линкийн 500 алдаа (BUG-07), ногоон «Устгах» товч (BUG-09), арилахгүй мессеж (BUG-10) гэсэн 5 согог. Couch Potato аялал 4 согог олсон (хоосон оролт BUG-01, хүрээнээс гадуурх он BUG-04, том/жижиг үсгээр хайлт BUG-05, давхардал BUG-06), харин Saboteur (curl) аялал зөвхөн 1 согог (BUG-08: буруу JSON-д 200 OK) олсон ч энэ нь UI-аас огт харагдахгүй цорын ганц API согог байлаа. Тоогоор Supermodel тэргүүлсэн ч хамгийн ноцтой согогууд нь Couch Potato-гийн хоосон ба хилийн оролтоос гарсан. Charter-ийн хүрээнд олдсон ихэнх согогоос гадна санамсаргүйгээр олдсон зүйл бол арилахгүй «Ном нэмэгдлээ» мессеж (BUG-10) ба биеггүй POST хүсэлт `201 Created` буцааж хоосон ном үүсгэдэг явдал байв. Шалгагдаагүй үлдсэн зүйлс: хэт урт гарчиг, `<b>` ба `&` зэрэг тусгай тэмдэгт, он талбарт үсэг/сөрөг/бутархай тоо, 1000 ба 2100 хилийн утга, байхгүй хаягтай API хүсэлт (жишээ нь `/api/books/999`), байхгүй id-тай DELETE. Эдгээрийг дараагийн session-ий charter болгоно. Playwright автомат тест BUG-01, 03, 04, 05, 06 зэргийг (мөрийн тоо, тоолуур, хайлтын үр дүн), BUG-07 ба BUG-08-ыг (HTTP статус код) найдвартай барих байсан, учир нь эдгээр нь тодорхой хүлээгдэж буй утгатай. BUG-02 (онын формат) ч «1971» гэж assert бичсэн бол баригдах байсан. Харин ногоон товч (BUG-09) ба арилахгүй мессеж (BUG-10) нь хэн нэгэн «ийм зүйл шалгая» гэж бодож assert бичихгүй бол автомат тестээр баригдахгүй, тиймээс хүний нүдээр, exploratory аргаар олдох байсан. Дүгнэвэл автомат тест зөвхөн урьдаас төсөөлсөн зүйлийг шалгадаг бол exploratory тест урьдчилан бодоогүй согогийг илрүүлдэг тул хоёр арга бие биенээ нөхдөг.
